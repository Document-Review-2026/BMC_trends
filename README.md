# BMC未来技术趋势观点

## 一、超节点的运维分层与边界：职责、链路与协议

### 1.1 管理分层的演进

**技术判断：**

- 柜级管理单元的价值将进一步降低，未来池化节点分层可能替代柜级管理，形成新的管理分层。
- 池化资源的实时分配是有价值的技术方向。

**传统分层：** 集群管理（包含超节点管理）→ 柜级管理 → 节点管理 → 部件管理。

**支撑理由：**

- 超节点架构打破了传统节点的完整性，推动资源向柜级整合。
- 随着算力需求进一步增长，供电、散热、Scale-up互联等资源的分配逐步走出机柜。直流入柜、CDU柜液冷、跨柜Scale-up互联已箭在弦上，以机柜为边界的统一资源不再存在。
- 传统服务器设计经验表明，供电、散热的闭环控制能够带来性能、功耗与热平衡收益。
- 未来设备／整机的性能与功耗近乎每1—2年翻倍，进一步提升了池化资源实时分配的价值。

### 1.2 BMC的职责与挑战

**技术判断：** BMC横向存在集成Fabric Manager的可能性，纵向传统职责延续，但超节点架构演进也会给传统职责带来新的挑战。

**职责范围：** [网络管理]、资产管理、管理范围内的能效管理、部署管理、运维管理、可靠性管理、安全管理。

**各项职责的演进判断与支撑理由：**

- **能效管理：从节点内调节转向跨域联动。**  
  AI负载相较传统计算负载，具有变化陡峭、频率高的特征；相关资源又以跨柜池化方式提供，需要跨域协同调节。

- **运维管理：传统感知机制与故障分析能力面临更大挑战。**  
  智能部件和传感器数量激增，凸显传统传感器机制的数量瓶颈；芯片与配套固件复杂度快速提升、固件高速变化，叠加AI硬件快速迭代，使BMC往往能够感知故障，却难以准确给出原因和处理建议。

- **可靠性管理：部件故障预测与容错的难度持续增加。**  
  器件复杂度不断提升，对故障预测与容错能力提出更高要求。

- **安全管理：BMC作为平台可信根是一种方案趋势，同时需要承担多智能器件的安全管理、验证与度量。**

### 1.3 北向边界：链路与协议

- **链路判断：** 以太网是当前主流管理链路。
- **协议方向：** 支撑池化资源闭环控制的快速路径（fast path）；面向AIOps的机模接口（BMC-CLI）。

### 1.4 南向边界：链路与协议

- **链路方向：** 以USB推动南向管理链路归一化，统一管理链路。
- **协议方向：** 基于南向抽象层、PMCI相关协议及OBMF，并补充HAL层。

## 二、BMC智能化趋势

### 2.1 BMC智能化的三种可能路径

- **数据采集型：** 作为数据采集器持续轻量化，提供数据信息。
- **端侧工具与分析型：** 作为端侧数据闭环工具，引入一定的AI分析能力，解决固件故障定位、故障预测、功耗动态分配等问题，并提供自然语言语义接口。
- **语言模型集成型：** 直接在BMC中集成语言模型，对接AIOps。

### 2.2 小型化算法与嵌入式AI部署

**技术判断：** 未来算法小型化与嵌入式部署将越来越成熟。

**支撑理由：** 单位参数、单位内存所支撑的能力持续每年翻倍。

**实现挑战：**

- 通过stream boot、热部署和北向接入能力，支持AI能力的灵活部署与集成。
- 统一定义智能化开发框架。

### 2.3 AI能力的部署方式

**技术判断：** AI能力可采用外接或内置方式；内置AI能力与统一内存更能发挥BMC的低时延优势。

### 2.4 BMC直接集成语言模型的现实限制

**技术判断：** BMC直接集成语言模型对接AIOps的技术尚不成熟，当前在落地、价值实现和规模化协同方面存在限制。

**支撑理由：**

- **安全问题是根本原因。**  
  BMC权限高，很多命令本身不适合由AI直接操作。

- **单台BMC的信息范围有限，整体协同条件仍较长远。**  
  需要带内、网络等其他元节点同步支持智能运维，才能发挥整体价值。

- **AI技术尚不稳定，当前落地面临升级成本。**  
  技术变化可能导致客户局点的BMC需要全部升级，而当前只需升级网关／网管。

- **BMC难以同步支持智能化，当前难以形成整体价值。**  
  客户局点通常存在多厂商、多代设备混布；老设备的BMC内存等资源受限，版本也已基本不再更新。部分设备支持、部分设备不支持，难以真正产生价值。

- **海量BMC端点的组网与调用技术尚未就绪。**  
  AI面对少数网关端点与面对全部BMC端点，组网复杂度差别很大。当前AI Agent尚不支持同步调用成千上万个Agent，时延、效率、Token使用率及认证信息保存等问题都较为复杂。
